What works

Log in the way PuTTY taught you.

login as:, then user@host's password:, typed into the terminal and asked again after “Access denied”.

Check every host key before trusting it.

A SHA256 fingerprint for every new server, a host key cache, and a loud warning if a key ever changes.

Sign in with the keys you already have.

OpenSSH and PuTTY .ppk files, Ed25519 and RSA. Passphrases are asked at login and never stored.

Keep Telnet and Raw for the old boxes.

Telnet with window size and terminal type negotiation, and plain TCP for serial servers and switches.

Leave no trace on the phone.

No event log, no session logs, no analytics. Saved sessions hold settings, never passwords.

    Before you install

    No. It is an independent, unofficial app modelled on PuTTY by Simon Tatham. The code is new Swift, released under the MIT licence.

    RSA user keys are signed with SHA-1, which OpenSSH 8.8 and later reject by default. Use an Ed25519 key. RSA host keys and password logins are not affected.

    Password and public key. Keyboard-interactive is not supported, so a server that offers only that method will not accept a password.

    iOS suspends apps it cannot see. A connection survives a short switch of about 30 seconds; after that iOS closes it, and Restart Session brings it back.

    Your saved sessions and cached host keys. Private keys sit in the iOS Keychain. Passwords, passphrases and everything you type are never written down.

    Rlogin and Serial. iOS gives apps neither the privileged ports Rlogin needs nor serial lines. Encrypted .ppk version 3 keys are not read yet; version 2 keys are.
